## 三、⭐ 本周最重要的四个发现

### 1. 扫描件比例 0% —— 路径 C 可跳过 OCR

原计划预设"扫描件要上 OCR"，实测 2026 年披露的 2025 年报**几乎清一色是带文本层的电子 PDF**。
意义不只是省钱，更关键的是**避免 OCR 识别误差污染绿色词频统计**，对 `GW_text` 变量质量是实质提升。

### 2. `stocks.list_date` 全市场为空（0 / 5,553）

- **影响**：控制变量 **Age（上市年龄）无法构造**，而实证设计明确列了 Age。
- 连带坑：验收覆盖率若用它当分母起点，会把新股（如只有 22 个交易日）误判成"缺 99% 数据"。

### 3. `total_mv` 仅 2021-09 之后有值（全市场非空率约 37%）

- **影响**：规模控制变量 **Size 在 2018–2021 年整体缺失**，丢掉近 40% 样本期。
- **好消息**：事件研究的 CAR 窗口在 2025–2026，恰好落在有值区间内，**不受影响**。

### 4. 新浪资产负债表的权益字段口径不统一

不同股票分别叫 `所有者权益(或股东权益)合计` / `股东权益` / `归属于母公司股东权益合计`。
回填脚本必须做**兼容匹配**，只认一个名字会大面积漏字段。

## 四、遇到的问题与修复

| 问题 | 现象 | 修复 |
|---|---|---|
| 中文引号截断字符串 | `verifyPilot.py` 报 `SyntaxError: invalid syntax` | 报告文案里的引号改用「」/『』，不用半角双引号 |
| 覆盖率分母错误 | 40 家被判"覆盖率 < 95%"，实际都是新股 | 起点改用**该股首个交易日**（`list_date` 全空不可用） |
| 权益字段漏检 | 评估显示"关键字段齐全率 0%"，但单只测试明明有 | 改为**兼容匹配**三种口径，齐全率回到 100% |
| Windows 大小写重命名 | `src→Src` 一步会失败 | 走中间名两步；并 `git config core.ignorecase false` + `update-index --force-remove` 清残留 |
| `.gitignore` 路径未同步 | 改名后数据目录会失去忽略规则 | 同步 `data/*` → `Data/*`，并用 `git check-ignore` 逐条验证 |

**教训**：前三个 bug 是同一类——**"看起来跑通了，但数字是错的"**。
覆盖率 40 家、齐全率 0% 都不崩溃，只是**静默地给出错数字**，比报错更危险。

## 六、学到的

1. **计划要定期跟实际对账**：计划书按"九月只奠基"写，我们九月就把底座做完了，
   照着过期假设干活会白费力气。
2. **先跑小样本再扩量**：扫描件 10 家 13 秒验证整条链路，避免一上来跑 100 家才发现逻辑错。
3. **对账不能只看"没报错"**：覆盖数、字段非空率、判定分布都要查——本周三个 bug 全是静默错数字。
4. **数据源的字段名不保证一致**：同一接口在不同股票上列名可能不同，必须做兼容匹配。
