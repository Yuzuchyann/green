## 三、数据正确性交叉校验证据

光按你说的「有数据」不算数，得验它**内部自洽**：

| 校验项 | 结果 |
|---|---|
| 总资产 ≤ 0 的行 | **0 行** |
| 会计恒等式 `\|资产 − (负债 + 权益)\| / 资产` | **99.73% 的行误差 < 1e-9**（等同精确）<br>p99 = 2.16e-16 |
| 会计恒等式误差 > 1% 的行 | 19 行（0.01%），涉及 15 家公司 |
| `PRAGMA integrity_check` | **ok** |

那 19 行不是列名选错（用的都是标准口径 `所有者权益(或股东权益)合计`），
大概率是少数股东权益或数据源自身的口径差异，**建模前单独列出、winsorize 或剔除即可**。

**Lev 的分布也算证据之一**：中位数 0.400，最小 0.006，只有 685 行（0.4%）超过 1——
这些是资不抵债的公司（Lev 中位 1.14），在 ST / *ST 壳股里真实存在，
**不是数据错误，应该 winsorize 而不是删除**。

## 四、⚠️ 数据源缺陷：年报的公告日是错的

这是本次最重要的发现，直接决定了新变量怎么用。

新浪这接口**有「公告日期」列**，而 `fina_indicator` 的 `ann_date` 是 0%——
一开始以为是前视偏差的解药。但合理性校验揭穿了它：**只有年报行的公告日是错的**，
它给的是未来某一期的披露日：

| 报告期 | 新浪给的公告日 | 间隔 | 判定 |
|---|---|---|---|
| 20260630 | 20260818 | 58 天 | 正确 |
| 20260331 | 20260414 | 29 天 | 正确 |
| **20251231** | **20260818** | 242 天 | ❌ 拿了 2026 中报的日子 |
| **20241231** | **20260331** | 460 天 | ❌ 拿了 2026 一季报的日子 |

跨**沪市、深市、北交所** 4 家实测，年报行 **100% 复现**。

**处理办法**：脚本里加了 `credible_ann()` 过滤器——只有当
`0 ≤ 公告日 − 报告期 ≤ 150 天` 时才采信（法定披露上限折算最多约 120 天，留了余量），
越界一律**留 NULL**。

> NULL 是明确的"我不知道"；一个看起来合理但其实是错的日期，是伪装的"我知道"。
> 后者会静默毁掉整个滞后对齐，这正是我们昨天复盘出的那类问题。

过滤后的实际覆盖率：

| 报告期类型 | ann_date 可用率 |
|---|---|
| 一季报 0331 | 98% |
| 半年报 0630 | 94% |
| 三季报 0930 | 98% |
| **年报 1231** | **1%** |

复核确认：**越界行数 0**，过滤器工作正常。

**结论与后续**：年报的 `ann_date` 不可用。滞后对齐改用
`end_date + 4 个月`（Fama-French / Compustat 惯例），
或从巨潮补真实披露日（`reports.announce_date`——反正路径 C 本来就要爬它）。

## 五、踩的两个坑（都是能变通宵的那种）

### 1. 一次瞬时故障打断了整个批次

第一轮跑到第 617 家时，`sync_log` 写入抛
`OperationalError: attempt to write a readonly database`。
磁盘 603G 空闲、文件权限正常，**确认是瞬时故障**。

但真正的教训在别处：**当时脚本没有包住写库异常，异常直接终止了整个循环**。
修了三点：

1. `process()` 整体包 try —— 一家公司出错，不该让后面几千家陪葬；
2. 写库也要退避重试（之前只有网络请求有重试）；
3. 全程复用**一条**数据库连接 + WAL（原先每家开关三次，疑似句柄抖动）。

改完后续跑：进度从 625 家接着走，57.8 分钟跑完剩余 4,928 家，零失败。

### 2. `nohup` 没能保住后台进程

第一轮用 `nohup ... &` 起后台，外层任务壳被回收时子进程一起被杀，
而且 python 输出没 flush，日志文件 0 行。**好在逐家独立提交的设计生效了**——
被杀的那一刻，已完成的数据一行没丢，断点续传直接接上。

## 六、对实证设计的意义

`balancesheet` 从 0 行到 174,133 行，意味着三个控制变量落地了：

| 变量 | 构造 | 可用性 |
|---|---|---|
| **Size** | ln(总资产) | ★★★ 非空率 100%，2018 全程覆盖 |
| **Lev** | 总负债 / 总资产 | ★★★ 非空率 99.9%（0.4% 需 winsorize） |
| **BM** | 股东权益 / 市值 | ★★☆ 权益 98.3%，但市值 `total_mv` 仅 2021-09 后有值 |

⚠️ 注意 Size 补上了 `total_mv` 的一个缺口：`total_mv` 只有 2021-09 之后有值
（全市场非空率 37%），导致 Size 在 2018–2021 缺失。**总资产可以当它的替补**，
两条路都能算企业规模，互为稳健性检验。
