# 扫描件比例报告（试点）

> 交付物对应 RESEARCH_PLAN 中 **2026-10 月**：「100 家试点数据库 + 扫描件比例报告」。
> 本报告只回答一个问题：**年报里有多少是无法直接提取文字的扫描件**，
> 它决定路径 C（文本 / 大模型法）的 OCR 工作量与预算。

## 一、结论

- 有效样本 **98 家**，其中**扫描件 0 家，占比 0.0%**；文本版 98 家（100.0%）。
- 判定阈值：页均可提取字符数 ≥ 200 视为文本版（扫描件与文本版分布几乎不重叠）。
- 有效样本页均字符数中位数：**755**；**最低一家（南京银行）也有 436 字符**，远高于阈值——判定稳健，不是临界值侥幸通过。

### 这个结果意味着什么（对路径 C）

- **一个反直觉的好消息**：原计划预设"扫描件需 OCR"（`RESEARCH_PLAN` 路径 C 明确写了「扫描件上 OCR」），
  但试点显示 2026 年披露的 2025 年报**几乎清一色是带文本层的电子 PDF**，扫描件比例接近 0。
- **直接后果**：路径 C 的年报解析**可跳过 OCR 环节**——既省下 OCR 算力 / 费用，
  也避免 OCR 识别误差污染绿色词频统计（对 `GW_text` 变量构造质量是实质提升，不只是省钱）。
- **仍需验证**：可持续发展报告本身尚未检测（见第五节-3）；此外应复核"混合型"年报（前部图片、后部文本）。

## 二、方法

1. **抽样**：从本地 `greenwash.db` 的 `stocks` 表（全市场 5,553 只）随机抽样，seed 固定可复现。
2. **定位年报**：AkShare `stock_zh_a_disclosure_report_cninfo`（巨潮资讯），取「2025 年年度报告」正文（排除摘要 / 英文版 / 更正版）。
3. **下载**：巨潮静态资源直链 `static.cninfo.com.cn/finalpage/{公告日}/{公告ID}.PDF`。
4. **检测**：PyMuPDF 取前 10 页，统计每页可提取字符数，求页均。
5. **判定**：页均 ≥ 200 → 文本版；< 200 → 扫描件（需 OCR）。

## 五、局限（后续必须处理）

1. 样本为**全市场随机抽样**，尚未限定为「已披露可持续发展报告的公司」（该名单待中证 / 巨潮采集后确定），比例为核心样本提供**先验估计**，不等于最终总体比例。
2. 仅检测**前 10 页**，若个别年报前部为图片而后部为文本（混合型），可能被误判为扫描件；后续扩大检测页数复核。
3. 本报告只覆盖**年报**；路径 C 还需要可持续发展报告本身，其扫描件比例需另行统计。
