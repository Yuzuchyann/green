## 这周做了什么

- 确定统一数据源方案：行情、估值（市值/PE/PB）、财务全部走 **AkShare**，不再 Tushare + AkShare 混用（避免字段名、交易日历、复权方式不一致导致下游清洗出岔子）
- 新建 `src/fetch_akshare.py`：复用原有 7 表 SQLite schema 与 `sync_log` 断点续传逻辑，AkShare 数据写入同一批表，下游清洗代码零改动
- 在 3 只测试股（2024 全年）上跑通端到端流程并抽样核对数据质量
- 更新 `requirements.txt`：AkShare 升为主数据源，Tushare 降级为可选交叉验证备份（注释标明其 2000 积分墙）
- 提交 `b850c8b`「Add unified AkShare fetcher; demote Tushare to optional cross-check」，并推送至 Gitee + GitHub（用 `ls-remote` 验过两边 HEAD 均为该提交）

## 卡在哪儿

- AkShare 资产负债表接口 `stock_balance_sheet_by_yearly_em` 在 1.18.94 报 `NoneType not subscriptable`，拉不到 → `balancesheet` 表暂为 0 行
- AkShare 免费接口不返回财报实际公告日（ann_date），财务指标只能按报告期对齐 → 存在轻微前视偏差
- AkShare 东方财富日线源 `stock_zh_a_hist` 在当前网络环境连接被中止 → 改用新浪源 `stock_zh_a_daily`
- akshare 1.18.x 已移除 `stock_a_indicator_lg` → 改用 `stock_zh_valuation_baidu` 逐个指标拉取再合并

## 怎么解决的（或打算怎么解决）

- 资产负债表：接口调用包在 try/except 里，失败则跳过；Size 用 `total_mv` 代理，BM 暂缺并在论文中标注
- ann_date：统一置 NULL，论文中披露「按报告期对齐 = 前视偏差」这一局限
- 日线改新浪源、估值改百度源后流程稳定跑通
- Tushare 积分墙（仅 `daily` 免费，其余 2000 分变相付费）决定不依赖，全部免费数据由 AkShare 覆盖

## 这周学到的

- 「不混用数据源」不是洁癖，是审计可验证性的硬要求：字段名、交易日历、复权方式任一不一致，下游都会出问题
- 免费数据的真实边界：Tushare 的免费额度远比想象窄，AkShare 才是真正零门槛的主源
- 验证不能只看「跑通没报错」，还要抽样核对量级（如平安银行 total_mv≈1787 亿、pb≈0.45 是否合理）

## 冒出来的新问题

- 资产负债表有没有别的免费可得渠道？（后续年报解析或换接口）
- `stock_financial_analysis_indicator` 返回的是年报+中报混合、时间跨度很长（如平安银行 1989–2026-06-30），后续需筛选「研究窗口内（如 2018–2026）的年报」再做回归
- 全市场 5551 只一次拉，耗时与失败重试策略怎么定？是否分批？
- 事件研究需要真实公告日，AkShare 不给 → 是否从巨潮 cninfo 另取 ann_date？

## 2026-09-01 更新 · 50 只批量试点（验证批量稳定性）

- **目的**：按 8/31 既定方案，先跑 50 只试点验证脚本在批量下的稳定性，再正式拉全市场（避免一上来就 5551 只翻车）。
- **做法**：`fetch_akshare.py --reset --limit-stocks 50`，窗口用 config 默认全研究区间 `20180101–20261231`。`--reset` 是清掉 8/31 那次 2024 单年预演的进度，否则前 3 只会被 `is_done` 永久卡在 2024 窗口。**必须用 venv 的 python 跑**（`envs/default/Scripts/python.exe`）——裸解释器没装 pandas/akshare，首跑直接 `ModuleNotFoundError` 崩了。
- **拉取结果（全窗口）**：

| 表 | 行数 | 覆盖（sync_log 成功口径） | 区间 |
| - | - | - | - |
| stocks | 5,553 | 全市场 | — |

- **批量稳定性结论**：脚本循环 / 容错 / 断点续传逻辑都正常；但**沙箱网络代理间歇性 `502 Bad Gateway`**，新浪行情源约 36%（18/50）请求失败、财务源约 18%（9/50）失败。失败呈「成片」特征（行情 000016–000021、000060–000070 连续挂），判断是代理时段抖动，非个股 / 代码问题。
